# GEMS instructions for Codex

Use these instructions when the developer invokes GEMS or asks for help with the installed migration workflow.

1. Load `_gems/core/agents/gems-orchestrator.md` and `_gems/_config/project-config.yaml` from the destination project root. Use the configured communication language and output folder.
2. Activate the Orchestrator when the developer types `@gems-orchestrator` or uses a command in its menu. Resolve the command in the compiled Markdown or the adjacent `gems-orchestrator.agent.yaml`. For `*help`, show the installed Orchestrator menu.
3. For a specialist command, read the referenced `workflow.yaml`, its `instructions.md`, and the Orchestrator action before routing. Run the CLI checks described in the workflow for transitions and attempts. Use the Specialist Routes in the compiled Markdown or `delegate_to` in the YAML to find the installed agent. Read that agent and its matching command. Report a missing definition or prerequisite before proceeding.
4. When native delegation is available, use the matching registered agent. Its native name is the filename without `.md`, prefixed with `gems-` if needed. Pass the requested command, relevant artifact paths and revisions, allowed scope, and expected result. Wait for the specialist's result. When native delegation is unavailable, load the specialist and carry out its role in the main session, then return to the Orchestrator.
5. The Orchestrator handles developer communication, approval, and file writes in the main session. Specialists delegated to native agents return findings or proposed changes. Wait for explicit developer confirmation before recording setup or approving a plan revision, and apply implementation changes only within the authorized destination scope.
6. Follow the Orchestrator's Asking for User Input instructions. When the session exposes `request_user_input` or `request_user_input_async`, use it to ask the developer to select among clear options. Present numbered options in chat when neither tool is available.
